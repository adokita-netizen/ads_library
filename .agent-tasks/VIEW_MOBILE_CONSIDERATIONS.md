# モバイル対応視点 — スマートフォンでの利用体験

## 現状の問題

- PRO DATABASE テーブルはデスクトップ前提（多数カラム）
- サイドバーが画面を占有する
- モーダルがスマホで見づらい
- チャートが小さすぎて読めない
- タッチ操作に最適化されていない

---

## モバイル利用シナリオ

### いつモバイルで使うか
```
1. 外出先で競合の広告をチェック
   → ランキングの閲覧（READ中心）
2. ミーティング中にデータを見せる
   → ダッシュボード、チャート
3. 通知を受けてヒット広告を確認
   → 広告詳細画面
4. 簡単なフィルター操作
   → ジャンル、プラットフォーム切り替え
```

### モバイルでは不要な操作
```
- エクスポート（PCで行う）
- AI生成（文字入力が多い）
- 設定変更（頻度低い）
- 複雑なフィルター組み合わせ
```

## レスポンシブ対応の方針

### ブレークポイント

```css
/* Tailwind CSS のデフォルト */
sm:  640px   → スマートフォン横向き
md:  768px   → タブレット
lg:  1024px  → 小型ノートPC
xl:  1280px  → デスクトップ
2xl: 1536px  → 大型モニター

/* VAAP の判定 */
mobile:  < 768px   → カード表示、サイドバー非表示
tablet:  768-1024px → 簡易テーブル、サイドバー折りたたみ
desktop: > 1024px   → フルテーブル、サイドバー常時表示
```

## コンポーネント別対応

### 1. サイドバー

```
デスクトップ: 左側に常時表示（幅240px）
タブレット:   アイコンのみ表示（幅60px）、ホバーで展開
モバイル:     非表示、ハンバーガーメニューで展開（オーバーレイ）

実装:
  <Sidebar className="hidden lg:block lg:w-60" />
  <MobileMenu className="lg:hidden" />
```

### 2. PRO DATABASE テーブル

```
デスクトップ: 全カラム表示
  | # | サムネ | タイトル | 広告主 | ジャンル | スコア | 配信日数 | 推定費用 | プラットフォーム |

タブレット: 主要カラムのみ
  | サムネ | タイトル | スコア | ジャンル |

モバイル: カード形式に切り替え
  ┌─────────────────────────┐
  │ [サムネ]  タイトル...     │
  │          広告主名         │
  │ 🏷 美容  ⭐ 85  FB+IG   │
  │ 📅 45日  💰 ¥500K       │
  └─────────────────────────┘
```

### 3. AdDetailModal

```
デスクトップ: 中央モーダル（幅70%）
タブレット:   中央モーダル（幅90%）
モバイル:     フルスクリーンスライドイン（下から上）

モバイルのレイアウト:
  ┌──────────────────────────────┐
  │ ← 戻る        広告詳細   ⋮  │
  ├──────────────────────────────┤
  │                              │
  │     [動画/画像プレビュー]      │
  │                              │
  ├──────────────────────────────┤
  │ タイトル: XXXXX              │
  │ 広告主: YYYY                 │
  │ ジャンル: 美容               │
  ├──────────────────────────────┤
  │ ヒットスコア: 85             │
  │ ├── 継続性: 90               │
  │ ├── 消化額: 80               │
  │ ├── アクティブ: +10          │
  │ ├── クリエイティブ: 75       │
  │ └── トレンド: 85             │
  ├──────────────────────────────┤
  │ [LPを見る]  [コレクションに追加] │
  └──────────────────────────────┘
```

### 4. HitAdAnalysisView

```
デスクトップ: 2x3 グリッドのKPIカード + 横並びチャート
タブレット:   2x3 グリッド + 縦並びチャート
モバイル:     1列のKPIカード + 縦並びチャート（スクロール）

チャートの対応:
  - 横棒グラフ → そのまま（幅を100%に）
  - 円グラフ → サイズ縮小（200px → 150px）
  - 複合チャート → シンプル版に切り替え
```

### 5. フィルター

```
デスクトップ: サイドバーにフィルターパネル
モバイル:     フローティングフィルターボタン → ボトムシート

  ┌──────────────────────────────┐
  │ フィルター            ✕ 閉じる │
  ├──────────────────────────────┤
  │ ジャンル:                     │
  │ [美容] [健康食品] [ダイエット] │
  │                              │
  │ プラットフォーム:              │
  │ [Facebook] [Instagram]       │
  │                              │
  │ スコア: 50 ───●──── 100      │
  │                              │
  │ [フィルター適用]  [リセット]  │
  └──────────────────────────────┘
```

## タッチ操作の最適化

### タップターゲットサイズ

```
最小タップサイズ: 44px × 44px （Apple HIG推奨）
テーブル行の高さ: 48px（デスクトップ） → 56px（モバイル）
ボタンパディング: 8px → 12px
アイコンサイズ: 16px → 24px
```

### スワイプジェスチャー

```
広告カード:
  左スワイプ → コレクションに追加
  右スワイプ → 非表示

モーダル:
  下スワイプ → 閉じる

ページ:
  左右スワイプ → ビュー切り替え（要検討）
```

### プルトゥリフレッシュ

```typescript
// ランキング画面で下に引っ張って更新

  // touchstart, touchmove, touchend でジェスチャー検知
  // しきい値超えたら onRefresh() 呼び出し
}
```

## PWA（Progressive Web App）対応

### なぜPWAか
```
- App Store 不要でインストール可能
- オフラインでも前回データを閲覧可能
- Push通知が使える（将来）
- ホーム画面にアイコン追加
```

### manifest.json

```json
{
  "name": "VAAP - Video Ad Analysis Platform",
  "short_name": "VAAP",
  "start_url": "/",
  "display": "standalone",
  "background_color": "#0f172a",
  "theme_color": "#3b82f6",
  "icons": [
    {"src": "/icon-192.png", "sizes": "192x192", "type": "image/png"},
    {"src": "/icon-512.png", "sizes": "512x512", "type": "image/png"}
  ]
}
```

### Service Worker（キャッシュ戦略）

```
キャッシュ対象:
  - HTML/CSS/JS → Cache First
  - API レスポンス → Network First（フォールバック: キャッシュ）
  - サムネイル画像 → Cache First（1日TTL）
  - 動画 → Network Only（大きすぎる）
```

## パフォーマンス（モバイル向け）

### 最適化ポイント

```
1. 画像の遅延読み込み
   <img loading="lazy" />

2. サムネイルのリサイズ
   デスクトップ: 200x200
   モバイル: 100x100 → データ転送量1/4

3. テーブル → カードの切り替え
   DOM要素数削減（テーブルの多数のセル → カードの少ないDiv）

4. ページネーションの調整
   デスクトップ: 20件/ページ
   モバイル: 10件/ページ → 初期表示高速化

5. チャートライブラリの遅延読み込み
   const Chart = dynamic(() => import('recharts'), { ssr: false })

6. タッチ時のアニメーション
   will-change: transform を使って60fps確保
```
