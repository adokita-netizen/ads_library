# Security Audit Checklist

最終更新: 2026-03-01

## 目的
VAAP プラットフォームのセキュリティ監査項目を定義する。
デプロイ前および定期監査（月次）で使用する。

---

## 1. 認証・認可

### 現状
- [ ] API 認証: 現在なし（内部利用前提）
- [ ] フロントエンド認証: なし

### Phase 2 要件
- [ ] API キー認証の導入検討 (C95: CI-140)
- [ ] CORS オリジン制限が環境別に設定されている (CI-026: DONE)
- [ ] セッション管理の実装（マルチテナント時）

---

## 2. 入力バリデーション

### Backend (Agent C)
- [ ] SQLAlchemy パラメータバインドを使用（生SQL禁止）
- [ ] `escape_like()` が全 LIKE クエリに適用されている
- [ ] Pydantic スキーマで入力型を強制
- [ ] `MAX_PAGE_SIZE = 100` が全一覧 API に適用
- [ ] ファイルアップロードにサイズ上限がある（画像: 10MB, 動画: 100MB）
- [ ] パストラバーサル対策（`os.path.basename()` 使用）

### Frontend (Agent B)
- [ ] ユーザー入力の HTML エスケープ（React の自動エスケープで対応）
- [ ] `dangerouslySetInnerHTML` を使用していない
- [ ] URL パラメータのサニタイズ
- [ ] XSS 対策: 外部データの直接 DOM 挿入がない

---

## 3. 秘密情報管理

- [ ] `.env` ファイルが `.gitignore` に含まれている
- [ ] ハードコードされた API キー/パスワードがない (CI-025: DONE)
- [ ] DB パスワードが AWS Secrets Manager から取得されている
- [ ] Meta API トークンが DB `api_keys` テーブルに保存されている
- [ ] ログに秘密情報が出力されていない
- [ ] エラーレスポンスにスタックトレースが含まれていない（本番環境）

---

## 4. データ保護

- [ ] PII マスキングがエクスポート処理に適用されている (CI-085: DONE)
- [ ] ad_metadata に個人情報が保存されていない
- [ ] S3 バケットがパブリックアクセスブロックされている
- [ ] DB バックアップが暗号化されている
- [ ] 通信が HTTPS のみ（HTTP → HTTPS リダイレクト）

---

## 5. インフラセキュリティ

### AWS
- [ ] IAM ポリシーが最小権限原則に従っている
- [ ] セキュリティグループが必要最小限のポートのみ開放
- [ ] RDS が VPC 内にあり、パブリックアクセス不可
- [ ] NAT Instance のセキュリティグループが適切
- [ ] Lambda の実行ロールが最小権限
- [ ] S3 バケットポリシーが CloudFront OAI のみ許可
- [ ] SQS キューにデッドレターキューが設定されている

### Network
- [ ] CloudFront の WAF が有効（将来対応）
- [ ] VPC フローログが有効（将来対応）
- [ ] SSL 証明書が有効期限内

---

## 6. 依存パッケージ

### Backend
```bash
# 脆弱性スキャン
pip install safety
safety check --json

# 依存パッケージの更新確認
pip list --outdated
```

### Frontend
```bash
# npm 脆弱性監査
npm audit --audit-level=high

# 依存パッケージの更新確認
npm outdated
```

- [ ] 高危険度の脆弱性がゼロ
- [ ] 中危険度の脆弱性を把握し、対応計画がある
- [ ] 依存パッケージのバージョン固定（lock ファイル使用）

---

## 7. ログ・監査

- [ ] API アクセスログが記録されている
- [ ] 認証失敗ログが記録されている（将来対応）
- [ ] データ変更操作に監査カラムがある（updated_at, updated_by）
- [ ] ログにリクエスト ID が含まれている
- [ ] ログの保持期間が定義されている
- [ ] エラーログが構造化 JSON 形式

---

## 8. クローリング倫理

- [ ] robots.txt を遵守している
- [ ] レートリミットを守っている（429 時の Retry-After 遵守）
- [ ] User-Agent が適切に設定されている
- [ ] クロール対象のプラットフォーム利用規約を確認済み
- [ ] 取得禁止ドメイン/パスのガードリストがある (CI-102)

---

## 9. 障害耐性

- [ ] DB 接続プール枯渇時のフェイルセーフがある
- [ ] 外部 API 障害時の回路遮断（Circuit Breaker）がある (CI-062)
- [ ] バッチジョブの排他ロックがある (CI-091: DONE)
- [ ] Lambda のデッドレターキューが設定されている
- [ ] ECS のヘルスチェックが設定されている

---

## 監査スケジュール

| 項目 | 頻度 | 担当 |
|------|------|------|
| 依存パッケージ脆弱性 | 週次 | A |
| 秘密情報チェック | デプロイ毎 | A (CI) |
| API 入力バリデーション | 月次 | C |
| フロントエンド XSS | 月次 | B |
| インフラ設定 | 月次 | 全体 |
| クローリング倫理 | 四半期 | D |
| 全体セキュリティレビュー | 四半期 | 全体 |
