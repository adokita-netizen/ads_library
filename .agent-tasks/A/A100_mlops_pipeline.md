# A100: MLOpsパイプライン構築

## 優先度: 🅲 C（将来拡張）

## 前提
A10(トレンド検出), A12(ヒット予測), A22(ヒット予測ML) が実装済みであること。

## 問題
- MLモデルの学習→評価→デプロイが手動
- モデルの劣化検知・再学習トリガーがない
- モデルバージョン管理がない

## タスク

### Task 1: モデルバージョン管理
- S3にモデルアーティファクト保存
- バージョン番号・学習日時・メトリクスのメタデータ管理
- 最新モデルへのエイリアス管理

### Task 2: 再学習パイプライン
- EventBridge → Lambda → ECS で定期実行
- 学習データの自動収集（直近N日の広告データ）
- ハイパーパラメータの自動チューニング

### Task 3: モデル評価・ゲート
- 新モデル vs 現行モデルのA/Bテスト
- 精度劣化検知（ドリフト検出）
- 品質ゲートを通過した場合のみ自動デプロイ

### Task 4: 監視
- 予測精度の日次モニタリング
- 入力データ分布の変化検知
- アラート（精度低下/データドリフト）

## 完了条件
- [ ] モデルのバージョン管理がS3で動作（コード実装済み、AWS実環境でのアップロード確認待ち）
- [ ] 定期的な再学習が自動実行される（EventBridgeはECS直実行へ反映済み。workerイメージ更新後の再検証待ち）
- [x] 品質ゲートによるデプロイ制御が動作
- [ ] 精度モニタリングダッシュボードが存在（監視スナップショット生成済み、可視化統合は残）

## 制約
- ECS Fargateの計算リソース内で実行可能であること
- コスト管理：月額上限を設定
