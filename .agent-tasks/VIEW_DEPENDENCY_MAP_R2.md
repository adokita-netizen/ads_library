## 依存関係の詳細

### 強い依存（先行タスク完了が必要）
```
D-R2-1 (クロール) ──→ A-R2-3 (パイプライン実行)
  新規広告がないと分析パイプラインを実行する意味がない

A-R2-2 (デルタ計算) ──→ C (pro-ranking レスポンス更新)
  view_count_increase フィールドが存在しないとAPIに含められない

A-R2-6 (AlertEngine) ──→ C-R2-2 (通知API)
  AlertRule/AlertHistory モデルがないとAPI化できない
  ★ ただし C が独自にモデル作成することで回避可能
```

### 弱い依存（フォールバックで独立実行可能）
```
C-R2-1 (AIチャットAPI) ──→ B-R3-1 (AIチャットUI)
  B はフォールバック実装で先行開発可能

C-R2-2 (通知API) ──→ B-R2-6 (通知センター)
  B は localStorage フォールバックで先行開発可能

D-R2-2 (動画メタデータ) ──→ C (スコア計算)
  duration_seconds がなくてもスコア計算は動く
```

### 完全独立（並行実行可能）
```
A-R2-4 (DBリトライ)      ←→ 他の全タスク
A-R2-5 (バリデーション)   ←→ 他の全タスク
B-R2-1 (ダークモード)     ←→ 他の全タスク
B-R2-2 (ヒートマップ)     ←→ 他の全タスク
B-R2-3 (テーブルUX)       ←→ 他の全タスク
B-R2-4 (ジャンルフィルタ)  ←→ 他の全タスク
C-R2-4 (N+1解消)          ←→ 他の全タスク
C-R2-5 (ページング)       ←→ 他の全タスク
D-R2-3 (メディア精度)     ←→ 他の全タスク
D-R2-4 (LPクローラ)       ←→ 他の全タスク
```

## 最適実行順序（4エージェント並行）

### Day 1
```
A: A-R2-1 (データ品質修正)     ← まずデータの状態を把握
B: B-R2-1 (ダークモード)        ← 全画面に影響、先にやる
C: C-R2-4 + C-R2-5 (CI改善)    ← 独立、すぐできる
D: D-R2-1 (定期クロール)        ← データ増量の第一歩
```

### Day 2
```
A: A-R2-2 (デルタ計算)          ← ProRankingTable の表示に必須
B: B-R2-3 (テーブルUX)          ← ProRankingTable の操作性向上
C: C-R2-1 (AIチャットAPI)       ← Phase 2 の核心機能
D: D-R2-2 (動画処理)            ← メディアパイプライン完成
```

### Day 3
```
A: A-R2-3 (パイプライン一括)    ← D-R2-1 の結果を使う
B: B-R2-2 + B-R2-4 (並行可)     ← 新コンポーネント + 改善
C: C-R2-2 (通知API)             ← Phase 2 の核心機能
D: D-R2-3 (メディア精度)        ← video_url 回収率向上
```

### Day 4
```
A: A-R2-4 + A-R2-5 (CI改善)    ← 独立、すぐできる
B: B-R2-5 (オンボーディング)    ← Phase 2
C: C-R2-3 (外部連携)            ← Phase 2
D: D-R2-4 (LPクローラ)          ← LP メタ情報取得
```

### Day 5
```
A: A-R2-6 (アラートエンジン)    ← Phase 2
B: B-R2-6 (通知センター)        ← C-R2-2 完了後
C: テスト + 修正                 ← 統合テスト

```
